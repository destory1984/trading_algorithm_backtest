# bnf 동반급락 규칙 심화 작업 지시서 (초안)

작성일 2026.9.29. 상태: **초안. 사용자 승인 전에는 돌리지 않는다.** 승인되면 이 파일을 `SPEC2.md` 로 바꾸고 그대로 따른다.
같은 폴더(`bnf_backtest`), 같은 엔진(krxbt v0.2.1), 같은 데이터로 한다. 코드는 `src/deep/`, 결과는 `results/deep/` 에 둔다.

## 1. 목적

bnf 그리드(1,440개 조합)와 걸어가며 검증에서 가장 나았던 동반급락 규칙이 신호 알림 후보가 될 만한지 판정한다.

- 한다: 규칙 하나를 고정해 과최적화 점검(Deflated Sharpe, 같은 날 무작위 종목), 이웃 설정 안정성, 폭락 의존도, 비용·체결 현실성, 데이터 끊김으로 뺀 거래의 영향, 보고서
- 하지 않는다: 규칙 바꾸기, 새 그리드, 주문 코드, 증권사 API 연결, 유료 데이터

## 2. 심화할 규칙 (고정)

| 항목 | 값 |
|---|---|
| 시장 | 코스피 |
| 신호 | 종가 기준 25일선 이격도 ≤ 70 |
| 시장 필터 | 신호일 코스피 지수 이격도(25일선) ≤ 95 (동반급락) |
| 진입 | 신호 다음 거래일 시가 |
| 청산 | 종가가 25일선 이상이면 다음 거래일 시가, 아니면 보유 20일째 종가 |
| 손절 | 없음 |
| 포트폴리오 | 1억 원, 5자리, 자리당 평가금액의 1/5, 재진입 제한 없음 |
| 비용 | 기존 `config.yaml` 그대로(수수료 편도 0.015%, 슬리피지 편도 0.1%, 그해 매도세) |

고른 이유: 걸어가며 검증이 16해 중 15해 이 규칙(보유 10일 → 2021년부터 20일)을 골랐고, 그리드 거래당 기대값 1등(거래 804건, 거래당 +19.8%, 승률 80%)이다.
기존 포트폴리오 표의 +9.9% / -45% 는 손절 -8% 판본이다. 이 지시서의 포트폴리오는 손절 없음 판본이라 숫자가 다를 수 있다.

## 3. 먼저 밝혀 둘 한계

- **깨끗한 표본 밖이 없다.** 2008 → 2026 전 구간을 그리드, 포트폴리오, 걸어가며 검증에서 이미 보았다. 코스닥·합산 시장도 그리드에 들어 있었다. 그래서 판정은 과최적화 점검과 안정성으로 한다. 학습기(2008 → 2016)와 검증기(2017 → 2026) 나눔은 보고만 한다.
- **신호가 드물다.** 한 해 거래가 0 → 60건이고 2020년만 278건이다. 신호가 한 건도 없던 해가 4해(2014, 2016, 2017, 2025)다. 결과가 폭락 몇 번에 달려 있을 수 있다(4.5).
- **비교 지수에 배당이 없다.** krx_data 의 코스피는 가격 지수다. 판정에 쓰는 보유 비교는 연 1.7%(코스피 배당수익률 근사, `config.yaml` 에 적는다)를 날마다 나눠 더한 총수익 근사로 한다. 배당을 빼면 전략이 연 1.5 → 2%p 유리해 보이기 때문이다.

## 4. 할 일

### 4.1 기준 결과 (`base.py`)

- 기간 2008-01-01 → 2026-09-23 (krx_data 마지막 날, `config.yaml` 의 `deep.end` 로 고정). 이 날 뒤 데이터는 불러온 직후 잘라내고 단언문으로 확인한다.
- 거래 단위: 거래 수, 승률, 거래당 평균, 중앙값, 손익비, 최악 거래, 해마다 거래 수와 평균.
- 포트폴리오 단위: 연 수익률, 최대 낙폭, 샤프, 노출(종목을 든 날 비율), 투자 비중. 전체, 학습기, 검증기.
- 비교 기준(코스피 총수익 근사): 보유, 낙폭을 맞춘 보유(비중 w 로 매일 맞춤, 나머지 현금 0%), 노출을 맞춘 보유.

### 4.2 Deflated Sharpe (`overfit.py`)

- 거래 단위로 잰다(그리드의 시행이 거래 목록이라서). 샤프 = 거래당 평균 / 거래 수익 표준편차, T = 거래 수.
- N = **1,526** = 그리드 1,440 + 포트폴리오 변형 86(`portfolio_filters.csv` 26행 + `portfolio_slots.csv` 60행). 지수 대기(`park.py`)는 같은 거래에 돈 굴리는 방식만 다른 것이라 넣지 않는다. RSI 다이버전스는 다른 규칙이라 넣지 않는다.
- V = 그리드 1,440개 조합의 거래 단위 샤프 분산. 그리드 거래 목록에서 다시 계산한다.
- 함수는 `us_shortterm/src/deep/overfit.py` 를 복사한다. 다른 N, V 는 민감도로만 적는다.

### 4.3 같은 날 무작위 종목 (`monkey.py`)

- 질문: 이 규칙의 수익이 "이격도 ≤ 70 인 종목을 골라서"인가, "코스피가 폭락한 날 아무거나 사서"인가.
- 규칙의 신호일마다, 그날 `eligible` 인 코스피 종목 중에서 규칙이 산 종목 수만큼 무작위로 뽑아 같은 날 시가에 사고 같은 보유 규칙(25일선 회복 또는 20일)으로 판다. 2,000번. seed 42.
- 규칙의 거래 단위 손익비(PF)와 거래당 평균이 무작위 분포에서 몇 번째 백분위인지 낸다.
- 참고로 "신호일 무관 무작위 날짜·무작위 종목" 판본도 같이 낸다(판정에 쓰지 않음).

### 4.4 이웃 설정 안정성 (`neighbors.py`)

- 이격도 {80, 75, 70} × 시장 필터 {동반급락 99, 97, 95} × 보유 {10, 20} = 18칸, 손절 없음, 5자리 포트폴리오.
- 18칸 모두 기존 그리드 안의 값이라 새 시행이 아니다. 포트폴리오로 돌리는 것만 새로 한다.
- 칸마다 연 수익률, 최대 낙폭, 낙폭을 맞춘 코스피 대비 차이. 결과를 보고 규칙을 바꾸지 않는다.

### 4.5 폭락 의존도 (`crashes.py`)

- `stage2.crash_periods` 6개를 하나씩 빼고, 또 모두 빼고 거래 단위·포트폴리오 결과를 다시 낸다. 뺀다는 것은 그 기간에 신호가 난 거래를 없애는 것이다.
- 이익 집중: 전체 이익 중 가장 좋은 신호일 5일, 10일이 차지하는 비율.
- 해마다 포트폴리오 수익과 낙폭을 맞춘 코스피 대비 차이.

### 4.6 비용·체결 현실성 (`costs.py`)

- 슬리피지 편도 0.1%(기본), 0.2%, 0.3%, 0.5% 에서 거래당 평균과 포트폴리오 연 수익률.
- 폭락 다음 날 시가 체결의 현실성: 산 종목의 20일 평균 거래대금 대비 자리 크기(평가금액 / 5)의 비율 분포. 1% 넘는 거래 수와 비율을 적는다.
- 진입일 시가가 전날 종가보다 몇 % 갭으로 열렸는지 분포(보고만).

### 4.7 데이터 끊김으로 뺀 거래 (`breaks.py`)

- 엔진은 시세 끊김을 낀 거래를 결과에서 뺀다(그리드 조합당 60건쯤). 이 규칙에서 빠진 거래 수와, 그 거래를 기록된 가격 그대로 넣었을 때와 모두 -100% 로 넣었을 때의 거래당 평균, 포트폴리오 연 수익률을 낸다. 빠진 거래가 큰 손실이었다면 결과가 부풀려진 것이다.

## 6. 검증

1. 봉인: 모든 표의 마지막 날 ≤ 2026-09-23.
2. 재현: 4.1 의 거래 목록이 기존 그리드(코스피, 70, 손절 없음, 20, crash95)의 거래 804건과 같다.
3. 포트폴리오 대조: 손절 -8% 로 바꿔 돌리면 기존 `portfolio_filters.csv` 의 crash95 / 재진입 제한 0 행(+9.9%, -45%)과 같다.
4. Deflated Sharpe 손계산 한 건.
5. 무작위: 같은 날 뽑은 종목이 그날 `eligible` 이고, 한 신호일에 같은 종목이 두 번 뽑히지 않는다.
6. 이웃 18칸 중 (70, 95, 20) 칸이 4.1 과 같다.

## 7. 판정 기준 (결과를 보기 전에 고정)

아래를 모두 만족하면 "신호 알림 후보"로 올리고 8절로 간다. 하나라도 못 미치면 이 규칙은 여기서 멈춘다.

1. 거래 단위 Deflated Sharpe ≥ 0.95
2. 같은 날 무작위 종목 대비 PF 백분위 ≥ 0.95
3. 포트폴리오 연 수익률이 낙폭을 맞춘 코스피(총수익 근사)보다 전체, 학습기, 검증기 모두 높다
4. 이웃 18칸 중 12칸 이상이 낙폭을 맞춘 코스피보다 연 수익률이 높다
5. 슬리피지 편도 0.3% 에서도 기준 3 의 전체 구간을 만족한다
6. 가장 좋은 신호일 5일을 뺀 거래당 평균이 0 보다 크다

## 8. 통과하면 (별도 지시서로)

- 신호가 한 해 0 → 60건이라 3개월 모의 기록으로는 거래가 한 건도 없을 수 있다. 대신 매일 장 마감 뒤 신호를 계산해 신호가 날 때만 텔레그램(`TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` 환경변수)으로 알리는 알림을 켜고, 거래 30건이 쌓일 때까지 결과를 기록한다. 주문은 내지 않는다.
